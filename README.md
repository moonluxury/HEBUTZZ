# HEBUTZZ
河工开物开发

客户端模块边界与维护规则见 [架构说明](ARCHITECTURE.md)：业务服务由 `AppServices` 持有，答题分为会话、判题、内容视图与布局，组件样式由 `UiStyles` 管理，本地 JSON 通过 `LocalJsonStore` 原子写入。

界面已统一移除手动刷新、重新加载资料/卡图及重新获取套餐入口。收藏页同时移除专用工具栏，内容区使用腾出的高度；其他页面通过容器布局收起对应空位。进入页面、进入库存弹窗和业务操作完成后仍自动更新数据。支付确认和未完成赠送的结果查询属于业务操作，继续保留。

学习工作台现为唯一首页：打开根目录 `project.godot` 后按 **F5** 运行。左侧可进入总题库、错题库、河工开物、我的收藏。右侧横幅、四张统计卡片和题型分布只展示内容，原点击跳转及详情页已移除；仅“学习趋势”可以打开学习记录。横幅的开始 / 继续学习按钮已移除，答题从侧栏总题库或错题库进入。没有悬浮说明。仍支持 F9 切换深浅色、Ctrl + 滚轮调整字号和窄窗口滚动。全软件滚动条由 `UiResources` 统一隐藏，包括编辑器、弹窗和菜单内部的滚动条；保留滚轮、触摸及原有键盘滚动行为。

Esc 统一返回上一层：先关闭当前弹窗、下拉菜单、展开的资源预览或窄屏题号浮层；卡牌详情返回收藏总览，文章详情返回河工开物列表，答题页返回对应的总题库或错题库，各一级页面返回工作台，工作台不再跳转。返回时沿用题库/资源列表的筛选与滚动位置，长按不会连续跨层；页面“返回”按钮与 Esc 使用同一个入口，“结束练习”仍直接结束并返回工作台。专项检查：`python tools/run_workbench_checks.py --godot <Godot控制台程序路径> --script check_back_navigation.gd --visual`。

本轮外观以用户提供的“高清重绘版/简约风”整套设计为准：首页、总题库、错题库、河工开物、答题页与收藏空页共用 `scripts/minimal_page.gd` 的字体、字号、按钮尺寸、图标尺寸和颜色规范。首页使用白底、细分隔线与横向题型进度条，不再显示横幅插画。品牌继续使用用户原有河流标志。

答题页的题号列表位于右侧，支持点击题号、输入跳转和单独隐藏。2026-10-30 按最新要求，顶栏仅保留标记、讨论两个纯图标按钮，不显示文字；已移除新增的解析入口与右侧解析面板。题目标记独立持久化，讨论按整门题库共享并在原右栏内切换。窄窗口也为右栏预留空间，过窄时底部按钮分行排列。题号列表保留当前题、已答、未答状态，并为已标记题目显示小旗角标。接口、迁移、真实联调截图与部署边界见 [题库讨论交付记录](DISCUSSION_IMPLEMENTATION.md)。答题时按 **F6** 隐藏左侧导航与顶部返回/课程标题/计时/结束练习栏，答题区自动扩展，再按 **F6** 恢复。长按不会反复切换，填空框和代码编辑器聚焦时也有效；题目、答案、草稿、计时及题号列表的展开状态均保留。F6 仅作用于当前答题页，新开练习恢复普通布局；F9 切换主题和 Ctrl + 滚轮缩放不退出专注布局。

页面加载采用五项优化：`UiResources` 共用字体、主题和图标；题号列表按可见区域复用按钮；答题场景仅保留实际使用的控件；`StudyStats` 统一读取、校验并缓存题库，练习只复制题目列表；`PageRouter` 保留侧栏及最多 4 个非当前常用页面。总题库与错题库分别缓存，保留筛选和滚动位置，返回时刷新学习记录与错题；答题会话不缓存，新开练习仍创建新会话。题号聚焦时可用方向键、Home/End、PageUp/PageDown 移动，Enter/空格选择。

各课程题库在加载时统一按“单选 → 多选 → 判断 → 填空 → 输出 → 编程”分组，同类题保留原资料顺序；总题库和错题练习使用同一分组顺序。题干编号、右侧题号和输入跳转均使用当前练习中的连续序号。原题 ID、题目内容和来源编号保持不变，已有错题、学习进度、继续学习位置及编程草稿仍按原标识对应。验证：`python tools/run_workbench_checks.py --godot <Godot控制台程序路径> --script check_question_order.gd`。

加载回归：`python tools/run_workbench_checks.py --godot <Godot控制台程序路径> --script check_loading_optimization.gd`。同一命令换为 `--script profile_page_switches.gd --visual` 可记录首次及重复进入的资源加载、页面构建和首帧间隔；比较时关闭其他测试进程。缓存数量可在 `scripts/page_router.gd` 的 `CACHE_LIMIT` 调整，默认 4，不包含当前页面。

普通答题模式使用题干 26、选项 24 的基础字号，F6 专注模式使用题干 28、选项 24，题号列表字号不变。两种模式的题干均按内容占高，选项基础高度 56、间距 24；答题区高度不足 650 时改为高度 48、间距 16。多行题干和选项会自动增高，长题仍可滚动，Ctrl + 滚轮仍可整体缩放。字号参数位于 `scripts/minimal_quiz_view.gd` 顶部的 `QUESTION_FONT_SIZE`、`OPTION_FONT_SIZE` 及两项 `FOCUS_*` 常量，按钮尺寸和间距位于 `_apply_question_typography()`。加入错题库按钮始终保持页面底色；未加入时文字与图标使用普通颜色，已加入时固定为蓝色（深色模式使用浅蓝），悬停、聚焦和按下不会改变这个状态颜色。该反馈通过 `state_only_feedback` 单独启用，不改变其他按钮的样式。

已提交的题目再次点击题号或切回来时可重新作答，旧选择、输入和参考答案会清空，题号列表仍保留“已答”记录；未提交的选择和输入保留为草稿，编程题草稿也继续保留。再次实际提交会记一次作答，停留在当前结果上重复点击提交不会重复计数。F6、主题切换和窗口调整只改变显示，不开始新一轮作答。“结束练习”直接返回工作台。

图标素材位于 `assets/minimal/icons/`，每个图标单独导出为 384 × 384 透明 PNG，按参考选择原始线性图标轮廓，源文件、授权及导出工具均随项目保存；选中工作台仍复用原有实心房子图标。文字全部使用原生控件，采用 4 倍字体过采样，图标开启 mipmap 缩小过滤。界面现使用统一、可中断的颜色与透明度过渡，不使用循环装饰、卡片缩放、导航位移或悬浮说明。所有按钮统一取消聚焦蓝框及悬停时的蓝色边框渐变，键盘导航、回车操作和弹窗关闭后的焦点恢复继续可用。

总题库提供课程/题干搜索、课程类别和学习进度筛选。错题页读取原错题 ID，支持科目筛选、已练习/未练习筛选；“待复习错题”使用与总题库一致的课程卡片，只展示有匹配错题的科目，显示该科目的错题总数和已练习比例，可开始/继续复习。逐题列表和“查看全部错题”入口已移除。旧错题没有逐题日期和错误次数，因此不伪造示意图中的日期、次数与掌握度，趋势展示新版记录的每日答错次数。河工开物继续使用现有四条示例资源，已移除“默认 / 名称 / 分类”排序，按数据源顺序显示；搜索、分类、示例展开、正文和公告均保留。答题页通过 `scripts/minimal_quiz_view.gd` 共用外观，判题由 `QuizGrader` 处理，作答与草稿状态属于 `QuizSession`，错题存档由 `WrongQuestions` 管理，控制器协调视图与业务服务。

旧首页场景、脚本和入口已删除。各功能的返回首页按钮统一返回工作台。唯一首页为 `scenes/Workbench.tscn`，界面逻辑为 `scripts/workbench.gd`。“我的精灵”入口已替换为“我的收藏”：`scenes/MyCollection.tscn` 和 `scripts/my_collection.gd`；原有精灵历史存档保留，失效的精灵场景、主题及后台计时逻辑已移除。

收藏支持按系列展开、筛选和查看卡牌详情。卡片网格上下排间距缩小 5px；详情操作文案为“想要”，标记后仅在列表卡牌图片右下角显示蓝色实心心形，不新增文字行或改变卡片高度，取消后移除心形。详情页左侧在常规桌面宽度下每行展示 4 张卡片，较窄窗口自动减少列数；卡名右侧同行显示真实数量（如 `×3`），未知数量显示 `×—`，已知未拥有显示 `×0`。总览与详情共用紧凑的顶部布局，已删除“返回收藏”按钮及空白工具栏占位；详情按 Esc 返回总览。系列展开图标使用独立的 `assets/minimal/icons/collection-chevron.png` 素材，展开/收起旋转 90°，时长由 `ui_tokens.gd` 的 `CHEVRON` 控制（0.16 秒），减少动态效果时直接显示最终方向。

减少动态效果：启动时和窗口重新获得焦点时读取 `DisplayServer.accessibility_should_reduce_animation()`。返回 `1` 时关闭全部 Tween，`-1` 表示系统能力未知（例如 headless），不会宣称已取得系统偏好。统一接口 `/root/UiMotion.set_enabled(false)` 可立即结束现有过渡并直接显示最终状态；启动前设置环境变量 `HEGONG_REDUCED_MOTION=1` 也可关闭，不新增设置页面。触屏输入关闭 hover，真实鼠标输入恢复；失焦/隐藏时完成视觉过渡并暂停答题计时标签刷新，计时基准保持不变。

`ProfileStore` 自动加载项是统一资料状态与服务适配层，不是新账号系统。仓库没有正式认证、个人资料保存、卡牌头像保存、账号绑定或退出接口，也没有正式好友服务；当前不会产生示例用户、随机 ID、虚假保存或虚假退出。头像不支持上传图片。好友模块复用收藏赠送的 `request_friends` 数据源及新增社交适配契约，当前缺少好友服务时明确提示。版本信息读取 `application/config/version`；当前项目未提供该值，显示“当前构建未提供版本号”，没有套用 Android 导出配置或引擎版本冒充桌面应用版本。

后续真实服务接入契约（服务负责身份校验、字段权限、格式验证、持久化、请求超时及现有账号流程）：

- 已验证的会话由宿主调用 `ProfileStore.use_provider(adapter, {state: "authenticated", account_id: existing_account_id}, collection_adapter)`；初始未知会话用 `state: "loading"`，确认退出用 `state: "signed_out"`。资料加载失败不改变会话。切换会话同步清空旧资料并使旧请求失效；收藏继续使用已有账号分区机制，不删除存档。如果一个适配器同时实现收藏接口，可省略第三个参数。
- `request_profile(account_id)` 返回 `{ok, account_id, profile, editable_fields, message?}`。`profile` 为完整规范资料，字段为 `public_id`、`display_name`、`avatar_card_id`、`school`、`college`、`major`、`grade`、`bio`。`public_id` 必须为既有对外稳定 ID；内部账号键、昵称或令牌不会替代它。头像由 `avatar_card_id` 在公开卡牌目录中解析原画并圆形裁切；空 ID、未知卡牌或资源缺失回退默认头像，不再读取旧 `avatar` 路径。
- `editable_fields` 只包含允许修改的字段及其现有规则，例如 `display_name: {max_length: ...}`。没有权限项即只读；提供 `avatar_card_id: {}` 表示允许选择卡牌头像，客户端另需同账号完整库存且该卡数量大于 0。`public_id`、登录身份、角色、认证状态不参与编辑。
- `save_profile(account_id, patch, avatar_card_id)` 接收有改动的文字字段及卡牌 ID；空卡牌 ID 表示不修改头像，不接受文件路径或上传内容。正式服务须在与库存流转兼容的事务边界内校验身份、目录和当前拥有数量，再持久化并返回 `{ok: true, persisted: true, account_id, profile, editable_fields}`，其中 `profile.avatar_card_id` 必须等于此次选中的 ID。头像不消耗卡牌，拥有一张即可，不套用赠送至少保留一张的额度。失败保持原头像，允许重试；不会乐观替换已提交资料，会拦截重复提交和过期响应。已经提交的请求由统一状态层完成，不依赖窗口生存期。
- `request_account(account_id)` 返回 `{ok, account_id, login_method?, masked_email?, masked_phone?, message?}`；只展示明确脱敏的联系方式，不读取密码或令牌。可选 `open_account_settings(account_id)` / `begin_login()` 打开宿主既有账号流程；认证结果由宿主通过 `use_provider` 同步。`logout(account_id)` 只有返回匹配账号的成功结果后才清除当前会话，失败保留状态。
- 好友入口现进入同一「我的好友」模块，见下节与 `SOCIAL_SERVICE_CONTRACT.md`；收藏仍复用既有赠送业务和想要标记，不改变题库授权与学习记录。

专项验证：`python tools/run_workbench_checks.py --godot <Godot控制台程序路径> --script check_personal_center.gd --visual`。不加 `--visual` 为 headless 检查。`tools/fixtures/profile_provider.gd` 只供隔离测试，运行前拒绝正式用户存档路径，未注册到应用，也不参与发布资源。覆盖保存成功/失败/取消、权限、重复提交、头像预览与持久化、剪贴板成功/失败、好友查询时序、收藏入口缓存一致性、长文本、深色、窄窗口、焦点恢复、切换账号和离页请求。实际运行截图在 `outputs/profile-validation/`，其中 `01-current-no-service.png` 是当前未接入服务的状态，其余明确标注隔离测试资料，不代表正式账号服务已开通。

本轮最终验证结果：个人中心 headless 71 项、Windows OpenGL 实际渲染 72 项全部通过（实际渲染额外验证系统剪贴板，并恢复原剪贴板文字）；`check_loading_optimization.gd`、`check_minimal_design.gd`、`check_workbench.gd`、`check_quiz_focus.gd`、`check_motion.gd` 及收藏 `check_collection.gd --visual` 均为 0 失败。`git diff --check` 无空白错误。所有账号写入、切换、退出和错误场景只在独立 `workbench-check-*` 存档及测试服务中执行。

收藏原 headless 测试有一个既有测试时序限制：`capture()` 在该模式直接返回，布局尚未稳定就执行模拟点击，导致点击断言失败并超时。在 `.godot_appdata/profile_collection_settled.gd` 中仅给该测试的 headless capture 补上与视觉模式等长的布局等待，完整用例即通过；没有改动收藏业务或其原测试文件。正式网络认证、远端资料/头像持久化、真实绑定与退出、真实好友服务和实体触屏仍未验证，原因是仓库没有相关服务或当前没有对应设备。系统减少动画能力在 headless 返回未知值 `-1`，可控减少动画接口已验证。
